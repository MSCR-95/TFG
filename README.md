# alglab — Algorithm Lab Framework

A Python framework for running algorithm experiments at scale and analysing
results with standard non-parametric statistical tests.  It handles the full
pipeline: parallel execution with hard timeouts, structured JSONL output, and
a scmamp-compatible statistical analysis layer (Friedman, Iman-Davenport,
Wilcoxon, Bergmann-Hommel, Shaffer).

---

## Features

- **Declarative experiments** — define generation, execution, and analysis in a
  single YAML file; `alglab experiment run` orchestrates everything.
- **Parallel execution with hard timeouts** — each job runs in a separate OS
  process via `pebble.ProcessPool`; timed-out processes are killed, not hung.
- **Stateless algorithm lifecycle** — `before_run → run → after_run` separates
  I/O from computation; worker processes cache algorithm instances across jobs.
- **Decorator-based registration** — `@register_algorithm("name")` is all that
  is needed to make an algorithm available to the CLI.
- **Streaming JSONL output** — one JSON line per execution, recoverable on
  crash; compatible with `jq`, pandas, R, or any line-oriented tool.
- **scmamp-compatible statistics** — Wilcoxon signed-rank, Iman-Davenport,
  Hommel 1×N, and Bergmann-Hommel N×N corrections mirror the R reference
  implementation.
- **Publication-ready plots** — boxplot, kernel density, Q-Q, critical
  difference diagram, and corrected p-value heatmap in PDF/SVG/PNG.
- **Reproducible seeding** — `--seed N` derives a unique deterministic seed per
  file via MD5, so different instances always get different seeds from the same
  global value.
- **Reference implementations** — Max-2-SAT: brute force + five QUBO solvers
  (exact, simulated annealing, tabu search, steepest descent, random sampling).

## Installation

```bash
# 1. Clone the repository
git clone <repository-url>
cd AlgsFmwk

# 2. Install base dependencies (creates .venv/ and registers the alglab command)
uv sync

# 3. Optional: QUBO solvers
uv sync --extra qubo

# 4. Optional: development tools (pytest, ruff, mypy, pre-commit)
uv sync --group dev
uv run pre-commit install   # enables git hooks
```

Verify the installation:

```bash
uv run alglab --help
```

After changing source files, refresh the editable package before relying on
the CLI or integration tests:

```bash
uv sync --reinstall-package alglab
```

Use `uv sync --extra qubo --reinstall-package alglab` when testing QUBO
algorithms.

## Quick Start

### Option A — Declarative experiment (recommended)

Define all phases in a single YAML file and run the full pipeline in one
command:

```yaml
# experiment.yaml
generation:
  n_files: 30
  vars: "20"
  densities: "2.5"
  k: 2
  jobs: -1
  seed_base: 42

engine:
  algorithms:
    - maxsat_brute
    - maxsat_qubo_sa
  pattern: "*.cnf"
  recursive: true
  n_jobs: 4
  timeout: 30
  seed: 42

study:
  alpha: 0.05
  measures:
    - path: result.satisfaction_ratio
      label: Satisfaction
      higher_is_better: true
      aggregation: mean
    - path: run_duration_s
      label: Time (s)
      higher_is_better: false
      aggregation: mean
```

```bash
uv run alglab experiment run --name my_experiment --config experiment.yaml
```

Creates `experiments/my_experiment/{config,data,engine,study}` with all results,
matrices, and plots.

Useful follow-up commands:

```bash
# Inspect the manifest generated by the orchestrator
uv run python -m json.tool experiments/my_experiment/config/manifest.json

# Read the text report
sed -n '1,160p' experiments/my_experiment/study/analysis.txt

# Re-run from scratch into the same directory
uv run alglab experiment run \
    --name my_experiment \
    --config experiment.yaml \
    --overwrite
```

### Option B — Manual three-step workflow

**Step 1: Generate instances**

```bash
uv run python -m alglab.algorithms.max2sat.generator \
    --n-files 30 --vars 20 --densities 2.5 --k 2 \
    --jobs -1 --out data/max2sat/ --seed-base 42
```

**Step 2: Run algorithms**

```bash
uv run alglab run \
    --dir data/max2sat/ \
    -A maxsat_brute \
    -A "maxsat_qubo_sa:num_reads=200" \
    --pattern "*.cnf" --recursive \
    --n-jobs 4 --timeout 30 --seed 42 \
    --out-path output/results.jsonl
```

**Step 3: Analyse results**

```yaml
# study.yaml
input_jsonl: output/results.jsonl
alpha: 0.05
measures:
  - path: result.satisfaction_ratio
    label: Satisfaction
    higher_is_better: true
    aggregation: mean
  - path: run_duration_s
    label: Time (s)
    higher_is_better: false
    aggregation: mean
```

```bash
uv run alglab study run --config study.yaml --output report/
```

Writes `report/analysis.txt`, `report/matrices/*.csv`, and
`report/plots/*.{pdf,svg,png}`.

For reproducible debugging, add `--sort-files` to the run command. The default
streams files in filesystem order to avoid materialising large sweeps.

### Option C — Programmatic API

**Running experiments from Python:**

```python
import alglab.algorithms  # activates @register_algorithm decorators
from alglab.engine import Runner, JSONLResultSink, iter_directory_jobs
from pathlib import Path

jobs = iter_directory_jobs(
    Path("data/max2sat/"),
    algorithms=["maxsat_brute", "maxsat_qubo_sa:num_reads=200"],
    pattern="*.cnf",
    recursive=True,
)

runner = Runner(max_workers=4, timeout=30.0)

with JSONLResultSink(Path("output/results.jsonl")) as sink:
    for result in runner.run_stream(jobs):
        sink.write(result)
        print(f"[{result.status}] {result.algorithm} — {Path(result.file).name}")
```

**Analysing results from Python:**

```python
from alglab.study import run_study, StudyConfig, MeasureSpec
from pathlib import Path

config = StudyConfig(
    input_jsonl=Path("output/results.jsonl"),
    measures=[
        MeasureSpec("result.satisfaction_ratio", label="Satisfaction", higher_is_better=True),
        MeasureSpec("run_duration_s", label="Time (s)", higher_is_better=False),
    ],
    alpha=0.05,
)
paths = run_study(config, Path("report/"))
```

**Adding a custom algorithm:**

```python
# src/alglab/algorithms/my_problem/my_algo.py
from __future__ import annotations

from dataclasses import dataclass
from pathlib import Path
from typing import Any

from alglab.engine.core import Algorithm
from alglab.engine.registry import register_algorithm


@dataclass(frozen=True)
class MyContext:
    source_name: str
    data: list[str]


@register_algorithm("my_algo")
class MyAlgorithm(Algorithm[MyContext]):
    """Solve my_problem with a greedy heuristic."""

    def __init__(self, max_iter: int = 100) -> None:
        self.max_iter = max_iter

    def before_run(self, file_path: Path) -> MyContext:
        lines = file_path.read_text(encoding="utf-8").splitlines()
        return MyContext(source_name=file_path.name, data=lines)

    def run(self, context: MyContext, *, seed: int | None = None) -> dict[str, Any]:
        return {"line_count": len(context.data), "objective": 42}
```

Then import the module in your `algorithms/__init__.py` to activate registration,
and use `--algos my_algo` on the CLI.

Run it with constructor parameters:

```bash
uv run alglab run \
    --dir data/my_problem \
    -A "my_algo:max_iter=250" \
    --timeout 30 \
    --out-path output/my_algo.jsonl
```

Algorithm parameter values are parsed as `bool`, `int`, `float`, then `str`.
Constructor arguments must be hashable because worker processes cache algorithm
instances by `(algorithm_name, sorted_kwargs)`.

## Common Workflows

### Compare solver quality and runtime

```yaml
study:
  alpha: 0.05
  measures:
    - path: result.satisfaction_ratio
      label: Satisfaction ratio
      higher_is_better: true
      aggregation: mean
    - path: run_duration_s
      label: Run duration
      higher_is_better: false
      aggregation: median
```

Use `run_duration_s` when you want to compare only the algorithm core. If setup
and verification matter, precompute a total duration from
`pre_run_duration_s + run_duration_s + post_run_duration_s` before studying it.

### Resume a partial run

```bash
uv run alglab run \
    --dir "$(pwd)/data/max2sat" \
    -A maxsat_qubo_sds \
    --out-path output/results.jsonl \
    --append
```

When appending, use the same `--dir` form every time. Mixing relative and
absolute paths creates different `file` values for the same instance, so the
study layer treats them as different benchmarks.

### Analyse failures as data

By default, the study pipeline filters to `status == "ok"`. If you want to
analyse a numeric field present on non-ok rows, use `prepare_matrix(...,
filter_status=False)` from Python and ensure the field exists for those rows.

## Architecture

Three independent layers connected only by the JSONL file format:

```
┌─────────────────────────────────────────────────────────┐
│                        CLI (_cli)                       │
│         alglab run     alglab study     alglab experiment│
└──────────────┬──────────────────┬───────────────────────┘
               │                  │
┌──────────────▼────────┐  ┌──────▼──────────────────────┐
│        Engine         │  │           Study              │
│  Registry · Runner    │  │  io · stats · plots          │
│  Jobs · Sinks · Worker│  │  analysis · schema           │
└──────────────┬────────┘  └─────────────────────────────┘
               │                  ▲
               │            results.jsonl
               ▼
┌──────────────────────────────────────────────────────────┐
│                      Algorithms                          │
│         max2sat: brute · qubo_sa · qubo_ts · …          │
└──────────────────────────────────────────────────────────┘
```

**Key design decisions:**

- **Process pool (pebble)** — each job runs in a separate process; hard timeouts
  are enforced by the OS, which threads cannot guarantee.
- **Lazy registration** — algorithms register at import time via decorator;
  workers import `alglab.algorithms` in their initialiser to populate the
  registry in spawn mode (macOS/Windows).
- **Stateless algorithm instances** — per-file data lives in the `context`
  returned by `before_run`, so cached instances can process many jobs safely.
- **Engine / study separation** — the engine never imports numpy/pandas/scipy;
  the study never imports pebble/multiprocessing.  Both layers are independently
  testable.
- **JSONL as the exchange format** — each `Result` is an independent line;
  the file is recoverable on crash and processable with any line-oriented tool.
